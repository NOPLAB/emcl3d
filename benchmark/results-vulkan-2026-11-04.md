# Vulkan GPU測定: 2000点・50粒子

最終コードの再測定は、ラウンド中央値の中央値7.731 ms、
全ラウンドの最大11.660 msで、測定した150更新すべてが50 ms未満だった。

## 環境と測定範囲

- AMD Ryzen 7 8840U / 内蔵Radeon 780M。
- WSL Ubuntu 22.04、GCC 11.4、ROS 2 Humble、Eigen、PCL、RelWithDebInfo。
- 実デバイス名は`Microsoft Direct3D12 (AMD Radeon 780M Graphics)`。
- Mesa Dozen 24.3.4、Vulkan API 1.2.296。実AMD GPUへD3D12経由で実行しており、
  lavapipe/llvmpipeなどのCPUソフトウェアVulkanではない。
- Dozenは非conformant・testing-onlyの警告を出す。ネイティブLinux RADVや
  本番環境での認証済みドライバの測定値とは扱わない。
- CPU affinityは0,2、CPUワーカー2。仮想CPUの制約であり、専有物理コアの保証ではない。
- 元と同じ外部`map_tsudanuma.pcd`、ボクセル0.2 m、2000点、50粒子、
  固定seedと初期共分散0.01。点数・粒子数・地図解像度を減らしていない。
- 5ウォームアップ後、30更新×5ラウンド。各ラウンドで再初期化する。

時間にはCPUでの問い合わせ準備、転送、GPU距離探索、同期・読み戻し、
CPUでの尤度・正規化・推定を含む。地図ロード、パイプライン作成、DDS、
TF、ROS点群前処理、配信は除外する。50粒子のコア更新を測るものであり、
既定500粒子のノード全体や他GPUの周期の測定値ではない。

## 反復改善

単にGPUへ移した最初の実装では、中央値93.124 ms、最大192.788 msで未達だった。
最初のhost-visible/coherentメモリを選ぶ方式を改め、静的地図をdevice-localへ、
入出力をhost-cached優先のメモリへ配置した。マッピングも毎回のmap/unmapから、
バッファ生存期間中の常時マッピングに変更した。

離散GPUでは地図をステージング経由でGPUメモリへ一度だけ転送し、
UMAではデバイスのメモリ属性に従う。non-coherentメモリのflush/invalidateと
転送・計算・host読み出しのバリアは省略しない。
これらを同時に変更した比較であり、各変更単独の寄与は分離していない。

## 整合性と依存分離

CPU専用はVulkanの検索を禁止した設定でもビルドできる。
GPU有効時も実行選択の既定値はCPUで、要求したGPUが使えなければ明示的に失敗する。
SDK・シェーダーコンパイラはGPUを含めるビルドでだけ要求する。

回帰テストでは、同じ不規則な511点の地図を使い、CPUスカラー探索と
GPUバッチ探索の距離、距離上限、バッファ拡大・縮小、端数workgroupを比較する。
フィルタ更新では姿勢、共分散、alpha、ESS、リセット、粒子と乱数系列を照合する。
GPUでFP64を要求せず、距離の平方根と尤度以降をCPUの既存精度・順序で計算する。

検出力の確認では、GPU距離を故意に4へ固定すると距離比較と更新一致が失敗した。
GPU結果の平方根をdoubleへ変える変異では、float丸め境界のalphaが1から0へ変わり、
専用テストが失敗した。実行選択のガード無効化と、ROSパラメータ転送の除去も
対応テストが検出した。すべて復元してから最終検証する。

CPU専用の2テストターゲット、Vulkan有効の3テストターゲットは、
探索関数のインライン化後にもすべて成功した。

CPU探索を別翻訳単位へ移した際の性能低下に対し、問い合わせ関数を
インライン化した。同じCPU affinity 4,8で連続測定したラウンド中央値の中央値は、
変更後65.912147 ms、直後の旧版（99a2d42）66.861962 msだった。
旧版にもラウンド中央値56.218〜69.413 msの変動があり、小差を高速化とは扱わない。
両者のchecksumは`2345.4296944`、リセット0だった。

ARM、Intel、NVIDIAなどの実GPU性能や実走行精度は未計測。
対応はGPU型式・ドライバ・利用可能なメモリ/dispatch上限に依存する。
CIのGPUジョブはx86_64/ARM64でのビルドとSPIR-V検証であり、実GPUでの性能試験ではない。
